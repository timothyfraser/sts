    LC 01 · observe

    With every stage in the browser, how many bytes cross the network on first load?

    If no stage runs on a server, what can the server send except the raw files?
    229,221 bytes: the points, the grid and the census table all go to the phone before it can join anything, and the modelled first load is about 1,173 ms.

    LC 02 · intervene

    Move the spatial join into PostGIS and cache it as a view. What re-runs when the user changes the neighbourhood filter?

    Press "show what re-runs" and watch which cards light up. Is the join upstream or downstream of the filter?
    2 stages re-run: the filter and the count. The join sits upstream of the input, so the view answers it; first load drops from 229,221 to 82,432 bytes.

    LC 03 · transfer

    What does a materialised view cost you, and when is it the wrong choice?

    Set the source data to change on every click and read the warning.
    A view stores a copy of the join and is only as current as its last refresh. With nightly refresh and data that changes on every click, the page shows "stale": cache stable, expensive joins, not live ones.
