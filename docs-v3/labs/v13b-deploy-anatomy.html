Chapter 13 · Deploying an API

Deploy anatomy: from manifest to running API

Learning objective: Trace a deployment from manifest.json to a running process on Posit Connect, and diagnose the common failures (missing package, missing env var, wrong entrypoint, cold start) from their log lines.

    LC 01 · observe

    Set Packages in manifest to "sf missing". Which step turns red?

    Restore installs only what the manifest lists. Read the log line under the red step.
    Start process turns red after 3 steps passed: restore succeeds because sf is not on the list, then the app dies with "there is no package called 'sf'".

    LC 02 · intervene

    Set Min processes to 0 and Request after idle to "yes". What does the user experience?

    All five steps stay green. Read "first response" and the timer.
    First response 8.55 s (8.4 s boot + 0.15 s). With min processes 1 it is 0.15 s; the deploy itself is healthy either way.

    LC 03 · transfer

    Why is a missing env var better failing loudly at start-up than returning a default?

    Set ALLOWED_ORIGIN to "never set", then to "unset, code defaults to *", and compare the two step strips.
    Never set fails at start process with 3 steps passed and a log naming ALLOWED_ORIGIN. "Unset, code defaults to *" shows all five green, 0.15 s, and a 200 health check: the API now accepts every origin, and nothing on screen points at the missing variable.
