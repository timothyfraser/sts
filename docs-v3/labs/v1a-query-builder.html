      LC 02 · intervene

      Move select(carrier, dep_delay) above mutate(gain = dep_delay - arr_delay). What happens and why?

      First set the select block to carrier, dep_delay (baseline also keeps gain), then press the up arrow on select once. Which columns are still in the table when mutate runs?
      The pipeline stops with "Error in `mutate()`: object 'arr_delay' not found". A pipe runs top to bottom, and each verb only sees the columns the verb above it passed on. The SQL twin fails the same way: the subquery no longer carries arr_delay. (Leave gain in the select list instead and select itself fails first: gain does not exist yet.)

      LC 03 · transfer

      SQL is written SELECT…FROM…WHERE but evaluated in a different order. Which clause does filter() correspond to, and why can WHERE not use a column alias defined in SELECT?

      Watch the logical-order strip: which clause lights up for filter, and where does it sit relative to SELECT?
      filter() keeps rows, which is WHERE. SQL evaluates FROM, then WHERE, then SELECT, then ORDER BY, so an alias such as gain is born in SELECT after WHERE has already run. ORDER BY comes after SELECT, which is why ORDER BY gain works in this lab.
