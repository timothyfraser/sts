    LC 01 · observe

    When does the job 15 */3 * * * next run after 10:00?

    */3 in the hour field means hours 0, 3, 6, 9, 12, ... counted from midnight, not from now. Read the refresh lane in "Next 5 runs".
    12:15. The hour field fires at 0, 3, 6, 9, 12, 15, 18, 21, so after 10:00 the next hour is 12, at minute 15. The lab's "next refresh" metric reads 12:15.

    LC 02 · intervene

    Inject a failure at 13:00 and rerun with append. What happens to the row count?

    The crash comes after the write but before the watermark moves, so the retry loads the same batch again. Watch "duplicate rows".
    The 13:00 batch (38 sites) is written, the job crashes, and the 13:05 retry appends it again: 912 rows become 950, with 38 duplicates. Switch to upsert and it stays at 912 with 0 duplicates.

    LC 03 · transfer

    Why should an ingest job be idempotent, and how does an upsert make it so?

    Compare the table after the fail + append state with fail + upsert. Which one looks like the day with no failure?
    Failures and reruns are normal on a clock. With ON CONFLICT (aqs_id_full, datetime) DO UPDATE (or rows_upsert() in R) the 13:05 retry rewrites the same 38 rows, so the table keeps 912 rows and 0 duplicates, exactly the no-failure day.
